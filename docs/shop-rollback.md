# 商店优惠价版本的回滚

`4a03475` 开始保存正常售价 `price_cents` 和独立优惠价 `promo_price_cents`。
`d767a70` 及更早的商店后端不能读取包含新字段的设置，会使公开目录返回 503。
保存了优惠价以后，保留旧文件并不代表可以直接恢复它们。

## 目标版本与入口

- 本次页面修复的回滚基线是 **4a03475 的后端及其配套前端**，都理解新优惠价模型。
- 不再使用一次性 `/tmp/hy2-deploy-shop-redesign.py` 的无校验 `restore()`。
  该脚本不在仓库中，本次未修改服务器上的临时脚本或生产文件。
- 仓库提供 `scripts/hy2_shop_rollback.py` 作为手工回滚入口；先做兼容检查，
  明确获准上线操作后才使用 `--apply`。未来发布脚本的异常恢复也必须走这个检查，
  不得重新使用直接复制旧后端的做法。
- 此入口只处理 **shop_store.py 与配套前端**；目标文件必须是可信的本地代码，
  其兄弟模块、接口及配置路径与当前运行环境兼容。它会导入目标代码以调用目标版本
  自己的 `validate_settings()`；不能把外来文件当作输入，也不是任意版本全站回滚工具。

例如在可信发布目录准备好目标文件后，先运行（替换路径和发布 ID）：

```sh
python3 scripts/hy2_shop_rollback.py \
  --runtime-root /opt/lancoai/shop \
  --store-file /path/to/trusted-release/web_api/shop_store.py \
  --release FRONTEND_RELEASE_ID
```

默认仅检查：不换代码、不切前端、不重启服务。输出不包含设置或凭据。
实际应用绑定 `/opt/lancoai/shop` 与 `lancoai-shop.service`；对其他临时目录传 `--apply`
会拒绝执行，防止用测试路径误重启线上服务。
`--apply` 才会执行 stop → 原子替换模块 → 切换前端 → start → 目录健康检查。
本次开发和测试没有对生产使用 `--apply`。

## 数据与失败处理

检查和执行期间持有部署锁及 `ShopStore` 保存设置使用的同一把文件锁。
不兼容、JSON 损坏、目标发布缺失会在停止服务之前被拒绝。加锁后重新读取当前设置，
因此独立检查之后管理员又编辑了数据，也不能绕过应用时的检查。

整个流程不重写商店设置，也不把新的优惠价转成旧版“原价”，更不恢复过时的设置快照。
执行失败时尝试恢复本次操作前的模块和前端，并重新检查目录；恢复也失败会明确报错。
服务切换期间有短暂停机，后台保存可能因持锁超过 2 秒而提示重试。

它不是断电/强制终止后的持久恢复事务。操作前仍需保留当前模块、前端发布及正式备份；
不要与另一个已持有部署锁的外层命令嵌套执行。若以后把商店回滚接入全站自动发布，
应使用统一发布事务持有锁，并把同样的目标版本校验纳入恢复阶段。

## 回归验证

`tests/test_shop_rollback.py` 用虚构设置验证：d767a70 校验器拒绝新状态且零切换、
兼容目标切换后设置字节不变、锁覆盖切换过程、健康检查失败恢复、坏状态拒绝。
历史校验器以原样摘录的夹具保存在仓库中，不依赖 CI 克隆完整 Git 历史。
所有测试应在项目的生产状态隔离环境中运行；不要用真实设置代替测试夹具。

# 配置管理写路由拆分设计

## 目标与范围

继续既有后端模块化工作，保持 HTTP 行为和业务写入语义不变，不提交、不推送、不部署。保留当前工作区已有改动。

首批仅抽取以下四个 POST 端点：

- `/admin/config/save`
- `/admin/rules/add`
- `/admin/rules/delete`
- `/admin/rules/raw`

管理员改密、更新、倍率调整和规则包应用不在首批范围。规则包包含用户配置修改；设置页面的动作跨越认证和运维，不应作为普通模板操作一起迁移。

## 方案比较

1. 推荐：独立 `admin_config_routes.py`，注入显式回调，原业务存储函数不动。与现有只读分发器一致，便于检查行为等价。
2. 将所有 POST 一次移入新文件：主文件减少更多，但职责混杂仍存在，回归范围过大。
3. 同时重构存储服务和路由：最终边界更彻底，但会混入事务与锁实现变化，不适合本轮兼容性提取。

## 接口与执行顺序

新模块提供 `handle_write(handler, context, *, path, form) -> bool`。未知路径返回 False，不调用鉴权、渲染和存储回调。命中后保留现有登录检查，再执行对应端点。

主服务继续拥有跨站请求检查、请求体大小限制、表单解析、请求级上下文和异常处理。分发调用放在原配置保存分支的位置，其他路由先后顺序不变。

上下文显式注入鉴权、公开主机名解析、编辑器渲染、模板校验和四个模板修改函数；不反向导入主服务，不复制其全部全局变量。

## 必须保持的行为

- 模板保存保留空内容、JSON 和 schema 错误的 422，版本冲突的 409，存储失败的 503，以及草稿和版本字段回显。
- 规则增删保留字段校验、错误跳转、版本冲突、删除目标校验和成功跳转。
- 原文规则保存保留空内容、5000 条上限、规则校验、草稿回显和版本冲突。
- 原有模板修改函数继续负责锁、原子写入和版本校验；不新增服务重载，不改变实际写入文件范围。
- 未登录、跨站请求和无效输入不产生模板修改。

## 验证与交付

先以现有处理流程补充 HTTP 行为回归，再抽取代码；覆盖成功、未授权、跨站、参数错误、冲突和存储失败。保留并运行现有模板锁、并发、安全和表单恢复测试。

新模块同步加入部署复制、权限、快照和恢复白名单，纳入严格静态检查。运行完整质量脚本并独立复核，不访问线上配置。设计边界确认后再开始实施。

## 实施结果（2026-09-08）

- 四个写路由已迁入 `hysteria/admin_config_routes.py`，主服务保留原位置分发及所有公共请求保护；模板事务函数未修改。
- 新增 23 项回归。提取前 22 项既有 HTTP 行为通过，未知路由测试因新模块不存在失败；提取后相关模板锁、并发、安全、草稿恢复等共 80 项通过。
- 完整质量脚本：1403 passed，64 条既有 datetime 弃用警告，187.29 秒；静态检查及 10 个文件格式检查通过。Shell 语法和 diff 空白检查通过。
- 独立只读复核无可操作问题。主服务由 9085 行降至 8877 行。
- 未提交、未推送、未部署，保留此前未提交改动。

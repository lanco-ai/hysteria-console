# 后端规范化持续目标

用户要求以目标模式直接完成此前讨论的后端规范化工作。继续当前未提交工作，不推送、不部署；不改变页面、HTTP 接口、鉴权、锁顺序、版本校验或失败回滚语义。

## 完成标准

- 主服务不再集中实现各领域的页面正文、路由业务和存储事务；保留启动、HTTP 请求保护、依赖装配及必要兼容入口。
- 路由按配置、运维、用户管理、认证和用户自助职责分组，而非把整个大文件换个名字。
- 领域实现使用明确依赖，禁止全局命名空间复制或反向导入主服务以伪造解耦。
- 新模块全部登记部署、权限、备份与恢复，并纳入静态检查。
- 既有行为和新增边界回归通过；独立复核无未处理的重要问题。
- 不以单个模块拆完或测试暂时通过认定整个目标完成；最终逐项核对主服务剩余职责。

每一批先建立/运行现有行为基线和新边界测试，再做等价提取；每批做定向回归，跨领域与最终阶段做全量检查。任何改变业务规则或上线动作都不在自动执行范围。

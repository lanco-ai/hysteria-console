# 后端规范化：第一轮

> 本文保留第一轮实施记录。当前完整模块化进度及最终验收以 `backend-modularization-goal.md` 为准。

## 当前结构与维护规则

- `subscription_service.py` 负责启动、HTTP 保护与分发、依赖装配及兼容入口；页面正文、领域事务已按职责迁出。
- `*_routes.py` 承接各组 HTTP 业务；`*_views.py`/`health_presentation.py` 承接呈现；计费、身份、模板、会话、凭据、撤销及运维使用各自领域服务；`audit_log.py` 负责审计追加。
- 所有新增模块采用明确依赖，不反向导入主服务，不复制全局命名空间。兼容包装器每次装配当前依赖，以保留现有调用入口和测试隔离。
- 当前 65 个采用文件接受完整 F/I 静态及格式检查；主服务保留兼容导出、执行基础静态检查，并新增独立格式检查。已有模块的渐进采用策略不变。
- 新增部署文件必须同步登记 `deploy.sh` 的持久化列表、快照、复制和权限，以及 `scripts/hy2-deploy-recovery.py` 恢复白名单。本次 37 个新增后端模块已逐项核对。
- 测试应验证实际响应、文件状态及故障恢复，不依赖实现必须位于主服务。移动实现时可同步迁移故障注入点，不能删除原来的行为断言。
- `scripts/check-quality.sh` 是本地和 CI 共用入口。配置已就绪，但未推送、未部署，因此没有声称 GitHub 远端运行或线上生效。

以下为历史第一轮记录。

## 已落实范围

- 测试初始化先导入真实 fcntl，消除导入顺序导致文件锁被空函数替换的问题。不支持 POSIX 锁的平台在执行锁操作时明确跳过，不能伪装通过。
- 新增独立进程锁竞争测试及不支持平台的跳过行为测试。
- 首页纯渲染移至 `hysteria/public_views.py`，只接收页面包装函数和静态资源版本；原 `render_home(host)` 入口保留。页面正文逐字节保持不变，不读取业务状态。
- 新模块加入部署复制、权限设置、两套回滚登记及恢复白名单。不运行生产部署。

## 检查入口

在开发虚拟环境安装 `requirements-dev.txt`，然后执行：

```bash
bash scripts/check-quality.sh
```

只做静态检查：`bash scripts/check-quality.sh --lint-only`。
可用 `PYTHON=/path/to/venv/bin/python` 指定解释器。

- 全量覆盖 `hysteria/`、`scripts/` 和 `tests/` 的语法、未定义名字及部分明显逻辑错误。
- `public_views.py`、测试初始化及本轮两份测试额外检查未使用导入／变量、导入排序和格式。完整采用列表在检查脚本内；后续逐个模块扩展，不对历史代码做全量格式重写。
- 统一 4 空格、单引号、100 列格式目标；Ruff 按 Python 3.9 语法目标检查，不代表已完成所有 Python 版本的运行验收。
- 工具配置参照 [Ruff 官方配置文档](https://docs.astral.sh/ruff/configuration/)。开发依赖使用本轮验证的固定版本；间接依赖尚未完全锁定。

## GitHub 自动检查

工作流在 push 和 pull_request 时执行同一入口，使用 Python 3.12 与临时 Ubuntu runner。锁和部署测试需要 root，故仅在临时 runner 中提升权限；不连接生产服务器、不携带部署密钥、不执行上线。

工作流随代码推送后才会生效。本轮未修改 GitHub 分支保护规则；若要强制禁止红灯合并，还需将 `backend-quality` 设置为必需状态检查。

## 后续边界

第一轮只是建立可靠检查和抽离试点，主服务仍约 9300 行。下一轮再抽离登录渲染和只读处理器；暂不改变鉴权、计费、凭据轮换、文件锁顺序或原子写入。部署脚本的模块登记仍为显式列表，本轮未重构这一机制。

## 本轮验证

- 统一检查入口：全量基础静态检查通过，4 个采用文件的严格检查及格式检查通过；1336 项 Python 测试通过，64 条既有 datetime 弃用警告。
- 独立审查后加强了锁测试的冷导入条件；临时恢复旧导入判断时测试失败，恢复修复后两项环境测试通过。
- 手工输入未定义变量和不规范格式，确认检查器分别返回失败状态；不是只添加空配置。
- 首页正文哈希保持一致；部署与恢复相关回归均包含在全套中。线上未部署，GitHub 工作流尚未远端运行。

# AI 视频画布优先重构设计

**日期：** 2026-09-23

**状态：** 用户已确认规格，进入实现

**范围：** 现有 `/admin/video` React 页面、视频工作流 API、Grok2API 适配器

## 目标

把 AI 视频页收敛为一个以节点画布为中心的工作区。主要路径为：一个提示词生成多张候选图，用户挑选首帧和尾帧，再交给支持首尾帧的模型生成视频。桌面通过画布右键菜单添加节点；手机提供同等的触控添加入口。

页面移除重复的“分镜编辑”视图、任务记录抽屉、AI 创作助手和视频页内的服务配置入口。当前任务进度和生成结果保留在画布上。

## 现状证据

- `VideoCanvas.tsx` 已使用 `@xyflow/react`，有左侧节点库、节点拖放和连线，但没有画布右键菜单。
- `VideoPage.tsx` 同时维护节点画布与分镜编辑两种视图；工具栏包含任务记录、AI 创作助手和服务配置。
- `ImageRequest` 没有批量数量字段；provider 目前只抽取一张图。`first_last_frame` 能力固定为未验证，适配器收到尾帧请求会明确拒绝。
- 现有项目已有视频工作流、运行状态、素材上传和管理员接口，无需引入新的画布库或新服务。

## 方案比较与决定

1. **画布优先（推荐）**：保留已有 React Flow，移除重复分镜页面和常驻节点库，右键菜单负责创建节点。最大程度贴合用户给出的流程和截图，也直接减少重复布局。
2. **双视图并存**：继续保留分镜编辑标签，只把节点操作改成右键。改动较小，但提示词、图片和视频流程仍有两套入口，继续产生重复。
3. **步骤向导**：改成提示词、候选图、视频三步表单。上手简单，但不符合用户明确要求的画布右键加节点交互。

采用方案 1。

## 交互与页面结构

### 顶部工具栏

只保留作品名称/选择、保存状态和保存动作。视频页不再显示任务记录、AI 创作助手或服务配置按钮；全局服务与密钥设置由现有管理页面继续负责。

### 画布与添加节点

- 新作品显示一个提示词节点；节点内可直接编辑提示词。
- 桌面右键画布空白处显示紧邻指针的菜单，包括“添加提示词”“文生图”“图片素材”“首尾帧视频”“结果预览”。不支持的模型能力显示禁用原因。
- 选中提示词节点后从菜单添加“文生图”，新节点放在其右侧并自动连线；其他添加操作放在右键位置。
- 节点右键菜单提供复制和删除。连接仍需通过端口类型、缺失输入和循环校验。
- 移除常驻左侧节点库，让画布获得主要空间。手机以“＋”菜单代替右键，并将节点属性面板显示为可关闭抽屉。
- 右侧属性面板仅编辑当前选中节点的模型、画幅、批量数量、运动提示词和时长等参数。

### 多候选图与首尾帧

- 文生图节点支持同一提示词批量生成候选图，默认 4 张；控件可选数量范围为 1–10，但仅在上游服务确认接受 `n` 参数后启用。
- 候选图片在节点内形成图库；用户分别选择“设为首帧”和“设为尾帧”。文生图节点提供 `first_frame`、`last_frame` 两个角色输出端口，显示当前选中图片的缩略图，视频节点提供对应输入端口。
- 图片生成与视频生成分成两个明确动作：先“生成候选图”，选定首尾帧后再“生成视频”。视频运行复用已保存的图片素材，不重复提交图片生成请求。
- 首尾帧未选齐、连接缺失或素材已不可用时，视频节点禁用运行并指出需要处理的输入。
- 视频节点接收首帧、尾帧及运动提示词；成功后结果直接显示在预览节点，可播放、下载或重新选择帧后再运行。

## 执行与后端接口

- 扩展 provider 图片请求的数量字段和响应解析，使 `/v1/images/generations` 的 `data[]` 作为多张候选图处理，而非只取第一张。
- 工作流节点持久化候选素材引用及首尾帧选择；运行快照只记录素材 ID/受保护引用，不记录 API Key 或未经脱敏的上游响应。
- 支持按目标节点提交工作流：生成候选图只运行文生图节点及其依赖；生成视频只运行视频节点及依赖。角色输出从持久化的候选素材 ID 读取，视频运行不再次调用文生图。
- `first_last_frame` 能力按实际 provider/model 能力开放。支持时按确认过的协议传首帧和尾帧；不支持时保留工作流编辑，显示原因并阻止提交，不静默改为单帧生成。
- 运行状态显示在对应节点和紧凑的当前任务区；去掉页面加载历史运行列表的行为。

官方 xAI 文档当前描述了图片生成 `n=1..10`，以及 `grok-imagine-video-1.5` 的 `image` + `last_frame` 首尾帧请求。但现有适配器连接的是可配置的 Grok2API 兼容服务，官方 xAI 文档不能证明该服务也实现了相同协议。因此实现必须以目标 provider 的能力检查/适配器测试为准；不能把官方能力直接等同于当前代理能力。

## 删除范围与数据保留

- 移除 AI 视频页的任务历史入口、抽屉及历史列表读取；已有运行记录默认保留在服务端。
- 移除 AI 创作助手的页面入口、组件和直接服务它的 `/api/video/assistant/draft` 前端/后端接口。保留 `VideoAssistantResult` 数据结构，因为 AI 服务能力检测路由仍复用该 schema。
- 移除视频页到服务配置的链接；保留模型凭据存储、设置 API 和全局 AI 服务配置。
- 不删除现有工作流、图片素材或任务记录，不改动用户配置和密钥。
- 优先从已保存的节点图恢复工作流；旧 `storyboard` 字段保持可读取，保存时不因切换页面而清空。

## 验收

1. 桌面右键菜单按鼠标位置打开；提示词节点选中时添加文生图会自动连线。
2. 一次文生图运行返回多张可选图片；首帧、尾帧选择能在节点和边上正确体现。
3. 两个帧角色都选择后才能运行首尾帧视频；视频运行复用已生成图片，不额外重复生图。
4. provider 不支持批量或首尾帧时，界面显示明确原因，工作流不会伪报成功或退化执行。
5. 刷新后已保存的工作流、候选图引用和帧选择能正确恢复。
6. 视频页不再渲染分镜编辑标签、任务历史抽屉、AI 创作助手或服务配置入口；已有后台记录和全局设置仍存在。
7. 手机可通过触控添加节点、查看候选图并选择首尾帧；弹层不遮挡主操作。

## 验证计划

- provider 单元测试：`n` 请求、`data[]` 结果解析、首尾帧请求字段、能力不支持时拒绝执行及脱敏错误。
- run-service 测试：目标节点与祖先选择、候选素材复用、视频等待双帧选择、未知 provider 能力阻断。
- 前端测试：右键坐标/自动连线、候选图库首尾帧选择、执行反馈、旧工作流恢复、移动端添加菜单和页面移除项。
- 运行 TypeScript 类型检查、React 构建、相关 Python/provider/workflow 测试与目标浏览器验收。
- 自动化测试使用 mock provider，不发送真实计费生成请求。若真实兼容性仍无法从能力接口或既有证据确认，单独报告并在取得用户同意后进行付费 live smoke test。

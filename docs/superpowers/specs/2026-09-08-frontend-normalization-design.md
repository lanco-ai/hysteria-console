# 前端规范化设计

## 目标与边界

延续前端审查结论，整理现有服务端渲染页面，不迁移 React，不修改业务 API、权限或计费语义。保留当前中性配色方向、管理员五列用户管理表、既有链接与操作。此次完成标准包含自动检查、样式组织、脚本边界、公共工具与组件一致性，不以单纯拆文件代替完成。

## 现状

- `hysteria/admin.css` 包含 6026 行，混合公共页、管理员与用户页样式以及末尾覆盖规则。
- 页面由 `*_views.py` 等 Python 模块渲染，部分交互脚本和静态布局样式内联。
- `admin_poll.js`、`usage.js`、`codex_quota.js` 有独立轮询与部分重复工具。
- 已有 `tests/workspace_visual.cjs`、`tests/usage_refresh_browser.cjs`，但当前质量入口没有运行它们。

## 方案选择

采用渐进整理：保留 Python 渲染和原生 JavaScript，先建立保护网，再调整文件与组件边界。仅格式化不能解决混杂职责；整体迁移框架会扩大风险且不是本次需求。

## 样式设计

按设计变量、基础样式、公共组件、页面与响应式规则组织源文件。对原有级联顺序建立可验证基线，初次拆分保持等价；再逐个合并可证明冗余的规则，不凭静态字符串搜索删除动态使用的选择器。保留兼容的静态资源入口、缓存失效与部署路径，新增资源必须覆盖打包、分发和恢复流程。

颜色用语义变量表达背景、文字、边框、操作和状态；允许公共页与工作区有不同变量取值。统一输入控件、标签、错误提示、按钮层级、卡片间距、表格滚动。动态进度宽度不作为应当删除的内联样式。

## 脚本设计

将登录、用户面板、配置等页面内联交互逐页迁到静态脚本。服务端只输出结构和安全编码的数据，避免将未转义数据拼入可执行代码。脚本初始化不得重复绑定事件，并兼容不存在对应节点的页面。

仅抽取确实共享的格式化、转义和请求机制；轮询频率、页面可见性、取消请求、失败退避和明细懒加载仍由页面协调。抽取后保留各页面当前生命周期语义，不强行合并成单一轮询器。

## 自动检查和验收

1. 固定前端开发依赖和锁文件，提供可重复执行的 JS/CSS 检查入口并接入 CI；格式化与正确性检查明确区分。
2. 浏览器测试使用隔离的预览服务与虚构数据，不访问线上用户、令牌或生产状态；测试入口负责服务启动、就绪检测与清理。
3. 检查桌面、平板和手机宽度下的管理员及用户页面；五列表格、表单、弹窗、侧边栏、历史展开、热图尺寸和横向滚动保持正常。
4. 验证手动刷新、自动刷新、隐藏页面暂停、错误恢复、明细懒加载及刷新失效；公共工具覆盖成功、失败与超时路径。
5. 页面脚本抽离后检查登录交互、用户订阅切换、复制与二维码、配置页面交互；加载过程中无缺失资源或浏览器脚本错误。
6. 运行完整后端回归，验证模板渲染、静态路由、缓存和部署文件清单；审查差异确保不改变权限和业务结果。

## 执行顺序

先补检查和浏览器回归；再整理 CSS 分层；接着抽离页面脚本；提取公共工具；最后统一组件细节并做全量回归。每阶段记录验证结果，失败先定位再继续。

## 发布边界

本次先完成代码整理和验证，不直接修改运行目录或重启生产服务。提交、推送和部署前单独核对用户授权与提交范围，排除 `.env`、本地工具和真实数据。

# 本店库存（Gemini / Muse AI / 短信接码自有库存）

商家自己买到的 Gemini 领取链接、Muse AI 账号和短信接码激活码，可以放进商品后台侧栏的「本店库存」（`/admin/shop?view=inventory`），在前台按现货出售。页面顶部显示现货与已发货合计；每个规格一行，标题旁是现货 / 已发货件数，下面「发货」与「补货」并排（窄屏上下排列），再下面是现货明细和发货记录。

## 规则

- Gemini、Muse AI 和短信接码分类的规格可以加库存；已存在的库存即使来源被停用或删除，仍可在库存页管理和发货（`STOCKED_CATEGORIES`）。每次最多粘贴 500 行，每行最多 2000 个字符；页面按 UTF-8 JSON 大小拆成不超过 64 KiB 的请求，逐批确认。失败后保留尚未确认的内容，重试不会重复入库。每行一件；与该规格已有库存完全相同的行跳过。总量上限 2000 件。
- 内容只存在 `state/shop/inventory.json`（0600），已列入 hy2-backup.sh。列表、商品管理和公开目录只拿到件数；「查看」和发货是唯一返回内容的 POST 请求，页面 60 秒或离开标签页后隐藏。
- 商品资料：`state/shop/inventory-catalog.json`（0600）保存商品名称和规格快照，也加入正式备份。入库和来源刷新前保存，GET 不写文件；供应商下架后，本店的现货及发货历史仍可管理。旧库存尚无快照且商品已下架时，至少按 SKU 显示并允许发货，不猜测商品名称或自动上架。
- 草稿：切换商品管理、库存和采购页面会保留输入；刷新或离开时提示未保存。仅存在当前页面内存中，不写 localStorage 或 sessionStorage。已查看的账号内容在离开库存页面后隐藏。
- 前台：规格有现货时即视为可购买（即使供应商缺货或来源报价过期），卡片显示「现货 N 件」，商品页显示现货件数。未上架、来源被主动停用或删除的商品不会出现在前台；其它没有自有库存的过期报价规格继续禁止购买。
- 发货：「发货一件」取最早加入的一件并标记已发货，返回发货内容（Muse AI 附换绑邮箱、改密码、换绑 2FA 的步骤；Gemini 附领取说明；短信接码附本店接码页地址和二验、三验的用法）。每次请求带一次性令牌，重复提交只会返回同一件。已发货件数计入该商品的已售（`automatic_sold`）；短信接码例外，它已按收到的短信计入已售，发货不再重复计入。
- 纠错：未发货的一件可以删除；已发货的一件可以「退回现货」。

## 回滚

旧版本不认识 inventory.json，会忽略它：前台按供应商库存显示，已售中不再计入本店发货件数，文件保留。重新上线后恢复。

本次审核修复保持 `inventory.json` 的 schema 1 和所有字段不变；上一版库存功能可继续读取，新增加的商品资料文件会被旧版本忽略。回滚不会恢复供应商下架后的可售能力，但不会损坏库存或发货记录。
